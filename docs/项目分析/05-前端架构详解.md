# 05 前端架构详解

## 1. 技术栈

| 维度 | 选型 | 说明 |

## 3. 路由与权限

| 路由 | 组件 | 守卫 |
|:---|:---|:---|
| `/` | HomeRedirect | 按登录态跳 `/chat` 或 `/login` |
| `/login` | LoginPage | RedirectIfAuth |
| `/chat`、`/chat/:sessionId` | ChatPage | RequireAuth |
| `/change-logs` | ChangeLogsPage | RequireAuth |
| `/preview/doc/:docId` | DocPreviewPage | RequireAuth |
| `/admin/*` | AdminLayout + 子页面 | RequireAdmin（`role === "admin"`） |
| `*` | NotFoundPage | — |

守卫基于 `authStore` 的 `isAuthenticated` 与 `user.role`，非管理员访问
`/admin` 自动重定向到 `/chat`；401 / 未登录时清空凭证并跳登录页。

管理后台子路由（16 个）：dashboard、knowledge（列表/文档/分块三级）、
knowledge-graph、intent-tree、intent-list（+ 编辑）、ingestion、traces（+ 详情）、
change-logs、settings、sample-questions、mappings、agents（+ prompt）、users。

## 4. API 层设计

### 4.1 `api.ts`（axios 实例）

- `baseURL = VITE_API_BASE_URL || ""`（dev 走 Vite 代理，生产配网关前缀）；
- 请求拦截器：从 `storage.getToken()` 注入 `Authorization` 头；
- 响应拦截器：
  - 后端统一 `Result` 信封，`code === "0"` 时返回 `payload.data`；
  - `code !== "0"` → 拒绝并把 message 作为 Error；
  - 401 或"未登录"错误 → 清空凭证跳转 `/login`；
  - 网络错误 / 业务错误 → sonner toast。

### 4.2 服务模块

每个领域一个 service 文件，仅依赖 `api.ts`，页面不直接触碰 axios：

- `chatService`：`/rag/v3/stop`、反馈、推荐追问；
- `sessionService`：会话列表/消息/改名/删除；
- `knowledgeService`：知识库/文档/分块/搜索/预览/上传；
- `ingestionService`：流水线 CRUD 与任务；
- `intentTreeService`：意图树 CRUD + 批量启停；
- `ragTraceService`：Trace 列表/详情；
- `agentProfileService`、`settingsService`、`dashboardService`、
  `sampleQuestionService`、`queryTermMappingService`、`knowledgeGraphService`、
  `bizChangeLogService`、`authService`、`userService`。

## 5. 状态管理（Zustand）

### 5.1 `authStore`

`user / token / isAuthenticated` + `login / logout / fetchMe`；登录成功写
`storage`，刷新页面后从存储恢复并拉取 `/user/me`。

### 5.2 `chatStore`（核心状态机）

维护：`sessions`、`currentSessionId`、`messages`、`isStreaming`、
`streamTaskId`、`streamAbort`、`streamingMessageId`、`cancelRequested`、
`deepThinkingEnabled`、`thinkingStartAt`、`openedSourceMessageId`、
`recommendReveal` 等。

关键动作：

- `fetchSessions / createSession / selectSession / deleteSession / renameSession`；
- `sendMessage`：追加用户消息 → `createStreamResponse` 发起 SSE → 按事件更新；
- `cancelGeneration`：`AbortController.abort()` + `POST /rag/v3/stop?taskId=` 双保险；
- `submitFeedback`、`toggleSourcesPanel`、`loadRecommended` 等交互动作。

### 5.3 `themeStore`

明暗主题切换（配合 `components/ui` 的 class 策略）。

## 6. SSE 流式交互（核心）

### 6.1 `useStreamResponse.ts`

```text
createStreamResponse({ url, headers, retryCount: 2, retryDelayMs: 600 }, handlers)
  → { start(), cancel() }
```

- `fetch(url, { headers: { Accept: "text/event-stream" }, signal })`；
- `readSseStream`：`TextDecoder` 增量解码，按空行切事件，解析 `event:` /
  `data:` 行；`data` 尝试 JSON.parse，失败按原始文本处理；
- 事件分发到 handlers（`onMeta / onMessage / onThinking / onFinish / onDone /
  onCancel / onReject / onTitle / onError / onEvent`）；
- 网络中断时按 `retryDelayMs * 2^attempt` 指数退避重试（最多 2 次），
  `AbortSignal` 触发后立即停止不再重试。

### 6.2 事件 → UI 映射

| SSE 事件 | 前端处理 |
|:---|:---|
| `meta` | 记录 conversationId / taskId |
| `sources` | 存到消息的 sources，供来源面板 |
| `grounding` | 存到消息，供"推荐追问" |
| `message` (type=think) | 追加思考内容 + `ThinkingIndicator` 计时 |
| `message` (type=response) | 追加正文，滚动跟随，Markdown 渲染 |
| `finish` | 标记消息完成，写入 messageId / title，刷新会话列表 |
| `reject` | 展示"系统繁忙" |
| `cancel` | 展示已取消状态 |
| `done` | 结束流式状态，启用输入框 |
| `error` | toast + 错误态 |

## 9. 关键约定

1. **统一信封**：所有非 SSE 接口都走 `Result { code, message, data }`；
2. **鉴权头**：`Authorization: <token>`，登录/未登录由拦截器统一兜底；
3. **别名**：`@/` 指向 `src/`；
4. **类型集中**：SSE 载荷、消息、会话、来源等类型集中在 `types/index.ts`，
   后端字段变化时前端只需改一处；
5. **无重型组件库**：UI 全部基于 Radix + Tailwind 自绘，构建产物可控。
