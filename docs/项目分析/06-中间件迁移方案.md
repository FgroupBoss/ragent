# 06 中间件迁移方案（MySQL + Kafka + MinIO + Milvus）

> 状态：已执行（2026-08-13），见文末"执行记录"。
> 目标中间件组合：**MySQL 8.0.46（业务库）+ Kafka 4.3.1（消息）+ MinIO（对象存储）
> + Milvus 3.0.0（向量库）**，均来自 `E:\projects\新建文件夹` Docker 栈；
> Redis（栈内 8.10.0）继续承担会话/限流/幂等职责。

## 1. 目标与原则

- 业务主库从 PostgreSQL 切换为 MySQL（`mysql:8.0.46`，utf8mb4）；
- 消息队列从 RocketMQ 切换为 Kafka（`apache/kafka:4.3.1`，KRaft，无 ZooKeeper）；
- 对象存储继续用 MinIO（凭据切换为新栈账号）；
- 向量库从 pgvector 切换为 Milvus（`milvusdb/milvus:v3.0.0`，元数据 etcd，存储共用 MinIO）；
- Elasticsearch / LightRAG 维持关闭（`keyword.type=none` / `graph.type=none`）；
- 所有中间件连接地址保持 `127.0.0.1` 映射端口不变（新栈已占用对应端口）。

## 4. 改造域 A：PostgreSQL → MySQL

### 4.1 影响面清单（已逐项核查）

项目没有 XML Mapper，SQL 都在 Java 中（MyBatis-Plus 条件构造器 + JdbcTemplate
原生 SQL + 少量 `@Insert/@Delete` 注解）。PG 专属点如下：

| 位置 | PG 专属内容 | MySQL 适配 |
|:---|:---|:---|
| `framework/database/JsonbTypeHandler.java` | 使用 `org.postgresql.util.PGobject` 写 jsonb | 改为 `ps.setString(...)`（MySQL JSON 列接受合法 JSON 字符串）；读取本就 `getString` |
| `knowledge/dao/handler/GroundingChunkListTypeHandler.java` | 同上 | 同上 |
| `knowledge/dao/handler/SourceRefListTypeHandler.java` | 同上 | 同上 |
| `knowledge/dao/handler/StringListTypeHandler.java` | 同上 | 同上 |
| `knowledge/service/impl/KnowledgeDocumentServiceImpl.java` | `setSql("ingestion_spec = CAST({0} AS jsonb)")` | `CAST({0} AS JSON)` |
| `rag/dao/mapper/MessageFeedbackMapper.java` | 2 处 `ON CONFLICT (message_id,user_id) DO UPDATE ... WHERE` | `INSERT ... ON DUPLICATE KEY UPDATE`（MySQL 8.0.20+ 别名语法） |
| `rag/service/impl/SampleQuestionServiceImpl.java` | `.last("ORDER BY RANDOM() LIMIT ...")` | `ORDER BY RAND() LIMIT ...` |
| `framework/config/DataBaseConfiguration.java` | `PaginationInnerInterceptor(DbType.POSTGRE_SQL)` | `DbType.MYSQL` |
| `rag/core/vector/PgVectorStoreService/Retriever/Admin` | `?::jsonb`、`?::vector`、`metadata->>'doc_id'`、`embedding <=> ?` | 切换 `vector.type=milvus` 后这些 Bean 不再激活（`@ConditionalOnProperty`），代码可保留或删除 |
| `resources/database/schema_pg.sql` | JSONB / TIMESTAMPTZ / BOOLEAN / `now()` / gin、hnsw 索引 / `COMMENT ON` / vector 列 | 新建 `schema_mysql.sql`（见 4.2） |
| `resources/database/init_data_pg.sql` | 已核查无 PG 专属 DML（无 ON CONFLICT / nextval / `::`） | 可直接在 MySQL 执行，需小改 `now()` 等（可选） |

### 4.2 新建 MySQL Schema（`resources/database/schema_mysql.sql`）

按 `schema_pg.sql` 逐表转换，规则：

- `JSONB → JSON`（MySQL 8.0 原生 JSON 类型）；
- `TIMESTAMPTZ DEFAULT now() → DATETIME DEFAULT CURRENT_TIMESTAMP`；
- `BOOLEAN → TINYINT(1)`（或 MySQL `BOOLEAN` 别名）；
- `COMMENT ON TABLE/COLUMN → 行内 COMMENT`；
- `DEFAULT '[]'::jsonb → DEFAULT (JSON_ARRAY())`（8.0.13+ 支持表达式默认值）；
- `USING gin(metadata)` → 普通索引 `(collection_name)` 等；`hnsw` 向量索引删除；
- **`t_knowledge_vector` 表不再创建**（向量全部进 Milvus；MySQL 8.0 无 VECTOR 类型，
  VECTOR 需 MySQL 9.0+）；
- 统一 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`；
- 表名/字段名保持小写下划线（与实体映射一致），MySQL 在 Windows 上大小写
  敏感策略需保持 `lower_case_table_names` 与实体名一致（栈内默认）。

### 4.3 依赖调整

- `framework/pom.xml`：`org.postgresql:postgresql` → `com.mysql:mysql-connector-j`
  （Boot 4.1 BOM 管理，Connector/J 9.x 兼容 MySQL 8.0.46）；
- `rag/pom.xml`：删除 `org.postgresql:postgresql` 与 `com.pgvector:pgvector`
  （PgVector 类不 import pgvector Java 库，删除后仍可编译）；
- 保留 `spring-boot-starter-jdbc`（JdbcTemplate 仍用于 Milvus 之外的场景）。

### 4.4 数据初始化

1. 用 root 创建数据库并授权：
   `CREATE DATABASE ragent DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
   `GRANT ALL PRIVILEGES ON ragent.* TO 'app'@'%';`
2. 按序执行 `schema_mysql.sql`、`init_data_pg.sql`（改名 `init_data.sql`，内容可移植）；
3. 初始数据含 `admin/admin` 用户与意图树、示例问题等。

## 5. 改造域 B：RocketMQ → Kafka

### 5.1 现状（已核查）

- `framework/mq`：`MessageQueueProducer`（接口）+ `RocketMQProducerAdapter`
  （实现）+ `DelegatingTransactionListener`（事务消息监听）+ `TransactionChecker`
  （按 topic 注册的回查器）+ `RocketMQAutoConfiguration`；
- 生产者调用点：`KnowledgeDocumentServiceImpl.startChunk`（**事务消息**）、
  知识库删除清理（**事务消息**）、`MessageFeedbackService`（普通消息）；
- 消费者 3 个：`KnowledgeDocumentChunkConsumer`、`KnowledgeBaseCleanupConsumer`、
  `MessageFeedbackConsumer`（均 `@RocketMQMessageListener`）；
- 事务回查器 2 个：`KnowledgeDocumentChunkTransactionChecker`、
  `KnowledgeBaseCleanupTransactionChecker`；
- 消费幂等已有 `IdempotentConsume` 注解（Redis），可继续复用。

### 5.2 新设计

**依赖**：根 pom 删除 `rocketmq-spring-boot-starter`，新增 `spring-kafka`
（Boot 4.1 BOM 管理 4.1.0，kafka-clients 4.2.1）；`framework/pom.xml` 同步。

**生产者**：

- `MessageQueueProducer` 接口保留，新增 `KafkaMessageQueueProducer` 实现；
- `send(...)`：`kafkaTemplate.send(topic, keys, MessageWrapper JSON)`，Kafka
  自动建 topic（栈内 `KAFKA_AUTO_CREATE_TOPICS_ENABLE=true`）；
- `sendInTransaction(...)`：RocketMQ 的"先发 half 消息 → 本地事务 → 回查"
  在 Kafka 没有等价物，采用 **Outbox 模式（推荐）**：
  1. 新增表 `t_mq_outbox(id, topic, message_key, body_json, status, retry_count,
     create_time, update_time)`；
  2. `sendInTransaction` 在**同一个本地事务**内执行业务逻辑
     （`localTransaction`）并写入 outbox 记录；
  3. 事务提交后（`@TransactionalEventListener(AFTER_COMMIT)` 或定时扫描任务）
     投递到 Kafka，成功后置 `status=SENT`；
  4. 失败/未投递的记录由定时任务重试（带重试上限与死信标记）；
  5. 消费端 `IdempotentConsume` 保证 at-least-once + 幂等。
  - 简化备选：`sendInTransaction` 改为"先执行业务事务，提交后同步 send，
    失败重试"——实现简单但存在"DB 已提交、Kafka 未发出"窗口，不推荐生产使用。

**消费者**：

- 3 个消费者改为 `@KafkaListener(topics = "...", groupId = "...")`，
  处理逻辑不变；topic 名沿用（`knowledge-document-chunk_topic`、
  `knowledge-base-cleanup_topic`、`message-feedback_topic`）；
- `TransactionChecker` 与 `DelegatingTransactionListener` 随 Outbox 模式移除
  （回查语义由 outbox 状态机替代）；
- `RocketMQAutoConfiguration` → `KafkaMessageQueueConfiguration`（装配
  `KafkaTemplate` + 生产者 + outbox 调度器）。

**配置**（application.yaml）：

```yaml
spring:
  kafka:
    bootstrap-servers: 127.0.0.1:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
    consumer:
      group-id: ragent
      auto-offset-reset: earliest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
```

删除 `rocketmq:` 配置段。

## 6. 改造域 C：pgvector → Milvus

### 6.1 兼容性结论（已验证）

- Milvus 官方兼容表：**Milvus 3.0.x 服务端 ↔ Java SDK 3.0.x**
  （推荐 3.0.5，最新 3.0.6）；
- 项目当前 `milvus-sdk-java 2.6.6` 只兼容 Milvus 2.6.x，**必须升级**；
- 已下载并核对 **milvus-sdk-java 3.0.6** jar：项目用到的
  `io.milvus.v2.*` 全部 16 个类（`MilvusClientV2`、`ConnectConfig`、
  `CreateCollectionReq`、`SearchReq/InsertReq/UpsertReq/DeleteReq`、
  `FloatVec/BaseVector`、`IndexParam` 等）**均存在**，升级以版本号变更为主，
  最终以编译 + 冒烟验证为准。

### 6.2 改动

- 根 pom：`milvus-sdk.version` `2.6.6 → 3.0.6`；
- application.yaml：`rag.vector.type: pg → milvus`；
  `milvus.uri: http://localhost:19530`（不变，SDK v2 URI 兼容）；
- `MilvusConfig`（`@ConditionalOnProperty(milvus)`）激活，创建 `MilvusClientV2`；
- `MilvusVectorStoreService / MilvusVectorRetrieverService / MilvusVectorStoreAdmin`
  激活（均为 `@ConditionalOnProperty(milvus)`）；
- `VectorSpaceInitializer` 启动时自动创建共享 collection
  `rag_default_store`（1536 维 / COSINE，与 `rag.default.dimension`、
  `metric-type` 配置一致）；

  `t_knowledge_vector` 表从 MySQL schema 移除；
- 入库 sink 的向量写入自动走 `MilvusVectorStoreService`。

### 6.3 风险提示

- SDK 3.0.6 个别方法签名/行为差异需编译与运行验证（已确认类存在，属低风险）；
- Milvus 3.0 存储复用 MinIO `a-bucket`，无需额外配置；

## 10. 影响评估

### 10.1 代码

- Java 改动约 20 个文件，集中在 4 个领域：数据库方言（7-8 个）、MQ 层（8-9 个）、
  向量配置（2 个）、依赖（3 个 pom）；
- 接口与业务逻辑（聊天流水线、检索、入库内核、意图、限流、Trace）**不改变**；
- 风险集中在 MQ 事务语义重构（Outbox）与 SQL 方言遗漏点，通过编译 + 冒烟 + 回归覆盖。

### 10.2 数据

- MySQL：全新初始化（`ragent` 库），旧 PG 数据不保留；
- Kafka：全新，topic 自动创建；
- Milvus：全新，collection 自动创建；
- MinIO：全新，桶自动创建；
- Redis：全新，用户需重新登录。

### 10.3 风险点

1. **MQ 事务语义**：Outbox 模式与 RocketMQ 事务消息行为不等价（无"half 消息 +
   回查"），需按"最终一致 + 幂等消费"验收文档分块链路；
2. **MySQL 方言遗漏**：已扫描全部 SQL（JSONB/ON CONFLICT/RANDOM/CAST 等），
   但运行时仍可能暴露未覆盖点，靠冒烟补齐；
3. **Milvus SDK 3.0.6**：类存在已确认，方法签名差异需编译验证；
4. **MySQL 8.0 无 VECTOR 类型**：`t_knowledge_vector` 删除，向量查询全部走
   Milvus（`vector.type=milvus` 必须生效）；
5. **ES 9.5 / LightRAG**：维持关闭，无影响；
6. **凭据明文**：application.yaml 继续明文（可选改为环境变量）。

### 10.4 收益

- 完全使用目标栈原生组件（MySQL/Kafka/MinIO/Milvus），无自建 RocketMQ 容器；
- 向量检索从 pgvector 升级为 Milvus 3.0（分布式能力、可扩展）；
- Kafka 生态（流处理、连接器等）可复用；MySQL 运维生态成熟；
- 中间件统一容器化管理，数据可整机备份。

  （解析/分块成功，因未配置 embedding API Key 在向量化阶段按预期失败）；
